# 1.5.0 — Contraseñas permitidas por proyecto y force push sin cruzar subcomandos

- **Fecha**: 2026-10-31 · **Commit**: `8859f7e` (del espejo agent-plugin-synapse) · **Tipo**: feat
- **Visto en**: No consta en la historia

## Síntoma

- La firma de contraseña de `detect_secrets` bloqueaba valores conocidos y no secretos de un proyecto, sin forma de
  permitirlos.
- `git worktree remove --force …` seguido de `git checkout master` se bloqueaba como force push a `master`.
- `cd -` se resolvía como `cd` a HOME, así que el alcance del proyecto se calculaba mal.

## Causa

- No había configuración por proyecto para la firma de contraseña.
- Las regex de force push abarcaban `;`, `&`, `|` y saltos de línea, así que unían dos subcomandos (`2a9bda1`).
- `cd -` no recordaba el directorio anterior.

## Cambio

- `detect_secrets` lee `password_rule_values` de `.claude/synapse-secrets.json` en `$CLAUDE_PROJECT_DIR` (o el
  `cwd` del payload). Se omite la coincidencia solo si cada valor capturado es igual a un elemento de la lista
  (distingue mayúsculas); si el archivo falta o es inválido, se sigue bloqueando (`946b1b4`).
- Las regex de force push quedan dentro de un solo subcomando; `cd -` vuelve al directorio anterior.

## Prueba

`tests/cases/detect_secrets.json`: `secrets_allow_project_password_value_edit|write`,
`secrets_block_password_value_without_project_config`, `…_with_invalid_project_config`,
`secrets_block_real_password_with_project_config`, `…_not_exact_in_project_config`,
`secrets_block_mixed_allowed_and_real_password`. `block_dangerous.json`: `pass_push_delete_then_other_force_and_master`,
`dangerous_block_force_push_flag_after_branch`, `pass_cd_dash_returns_to_project` y `block_cd_dash_back_to_outside_dir`.

## Lección

Una excepción por proyecto tiene que ser exacta y fallar cerrada. Una regex de shell no debe cruzar los separadores
de subcomando.
